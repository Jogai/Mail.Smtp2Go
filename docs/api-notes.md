# API notes: where the live API and the documentation disagree

Observations recorded while implementing the typed clients, with the date they were made or the source they come from. Each is handled in code as described; re-check them when the reference pages change (the spec harvester of plan 08 diffs the OpenAPI fragments).

| Area | Documentation | Observed | Handling | Observed |
| :-- | :-- | :-- | :-- | :-- |
| `webhook/view` response | Example and schema show `data` as a single webhook object. | The live API returns `data` as an array of webhooks (the community library's live tests deserialise an array). | `WebhookListConverter` reads either shape into `IReadOnlyList<Webhook>`; an object becomes a one-item list. | Community library live tests, 2026-02 to 2026-03; docs page revision 2026-05-18 |
| `webhook/add` and `webhook/edit` response examples | `headers` and `usernames` are shown as strings (`"X-Test-Header"`, `"MyUser1"`) while the schema says arrays. | Not verified live. | `StringOrStringArrayConverter` on `Webhook.Headers` and `Webhook.Usernames` reads a string or an array. | Docs page revision 2026-05-18 |
| `webhook/add` `events` list | Eight values: `delivered`, `unsubscribe`, `spam`, `bounce`, `processed`, `reject`, `click`, `open`. | The Webhooks Overview also lists a Resubscribe event. | `WebhookEmailEvent.Resubscribe` is kept; contract tests should allow-list it. Same for `WebhookSmsEvent.OptOut`, which the overview lists but `sms_events` does not. | Docs, 2026-09-11 |
| Callback `event` names | `processed`, `delivered`, `open`, `click`, `bounce`, `spam`, `unsubscribe`, `resubscribe`, `reject`. | Live callbacks carry `opened`, `clicked`, `spam_complaint`, `unsubscribed`. | `WebhookEventFactory` maps both spellings to one `WebhookEventKind`; `EventRaw` keeps the wire value. | Community library captures, 2026-02-07 and 2026-03-24 |
| Callback field names | The parameter table lists `message-id`, `subject`, `user-agent`, `read-secs`, `client-device`, `geoip-*` with hyphens. | Form callbacks carry both `Message-Id` and `message-id`, `Subject` and `subject`; JSON callbacks have been seen with `Message-Id` and `Subject` in mixed case. `click_url` and `link` appear on click events but are not in the table. | Keys are normalised (lower case, `-` to `_`) and merged; `Link` and `ClickUrl` are modelled on `EmailClickEvent`. | Community library captures, 2026-03-24 |
| Callback `time` on SMS events | The SMS parameter table has `received_timestamp` and no `time`. | Not verified live. | `SmsStatusEvent.Time` falls back to `ReceivedTimestamp`. | Docs, 2026-09-11 |
| Template endpoints | Reference pages are `template/add`, `template/edit`, `template/delete`, `template/search`, `template/view`. | As documented. | The plan's `template/update` and `template/remove` names were not used; the client methods are `UpdateAsync` and `RemoveAsync` over the documented paths. | Docs, 2026-09-11 |
| Template name | `template/add` and `template/edit` return `template_name`; `template/search` and `template/view` return `name`. | As documented. | `Template` has both properties and `DisplayName`. | Docs, 2026-09-11 |
| `suppression/view` paging | The request has `continue_token` but no `page_size`; the docs describe `start_date` as defaulting to today at midnight and `end_date` to 30 days before today (reversed). | Not verified live. | No page size is modelled; the date descriptions are quoted as written. | Docs, 2026-09-11 |
| `archive/search` paging | The request documents `continue_token` "if too many results were found"; the response schema and example have no `continue_token`. | Not verified live. | `ArchiveSearchResult.ContinueToken` is read when present; `SearchAllAsync` stops after the first page otherwise. | Docs, 2026-09-11 |
| Archive download link | `ArchivedEmail.Url` "can be used to download the original email"; whether it needs the API key is not stated. | Not verified live (no archive-enabled key in the build environment). | `DownloadOriginalAsync` fetches without the key and retries with it on 401 or 403. Record the outcome here after the first live run. | Docs, 2026-09-11 |
| "Adjusting archives" page | Describes the account-level archiving setting; no OpenAPI fragment. | n/a | Nothing to model. | Docs, 2026-09-11 |
| `stats/email_summary` request | Only `username`. | The community library sends `start_date`/`end_date`, which the docs do not list for this endpoint. | Not modelled; `email_history` is the endpoint with a date range. | Docs, 2026-09-11 |
| `activity/search` `start_date` | The property's description key is misspelled `descriiption` in the OpenAPI fragment. | n/a | Cosmetic; the field is modelled from the text. | Docs, 2026-09-11 |
| `activity/search` and `subaccount_id` | The endpoint filters with a `subaccounts[]` array and has no `subaccount_id`. | As documented. | The endpoint row does not accept `subaccount_id`; `RequestOptions.SubaccountId` is ignored for it (with a diagnostic). | Docs, 2026-09-11 |
| `api_keys/edit`, `users/smtp/edit`, `ip_auth/edit` methods | Each path has a `PATCH` page ("patch ... ignoring missing properties"); `api_keys/edit` and `users/smtp/edit` also have a `POST` page with defaults for omitted fields. | As documented. | `EndpointTable` is keyed by path and method; `EditAsync` sends `POST` (full edit), `PatchAsync` sends `PATCH` (partial edit). `ip_auth/edit` has `PatchAsync` only. | Docs, 2026-09-11 |
| `api_keys/*`, `users/smtp/edit` (PATCH), `ip_auth/edit` response schemas | The `data` array's item schema lists `request_id` and `data` as if each item were an envelope. | The examples show plain key, user and IP objects. | The items are modelled as `ApiKey`, `SmtpUser`, `AuthenticatedIp`; the two schema fields are allow-listed in `known-unmodelled.json`. | Docs, 2026-09-11 |
| `users/smtp/*` response shape | `view`, `add`, `edit` (POST) and `remove` return `{"results": [...]}`; `edit` (PATCH) returns a bare array. | As documented. | `ResultsListConverter<SmtpUser>` (and `<AuthenticatedIp>`) reads both shapes into `IReadOnlyList<T>`; `ViewAsync` keeps the wrapper as `SmtpUserViewResult` because it also carries the default rate limit. | Docs, 2026-09-11 |
| `ippool` versus `ip_pool` | Requests take `ip_pool`; responses return `ippool`. | As documented. | Both map to `IpPool`. | Docs, 2026-09-11 |
| `ip_auth/view` item schema | The schema key is `ip_addres` (sic). | The example uses `ip_address`. | Modelled as `ip_address`. | Docs, 2026-09-11 |
| `api_keys/remove`, `ip_auth/remove` responses | Empty schema, no example. | Not verified live. | `RemoveAsync` returns `ApiResponse<JsonElement>`. | Docs, 2026-09-11 |
| `single_sender_emails/view`, `sms/view-received`, `sms/view-sent` examples | `request_id` is nested inside `data` and absent at the top level. | Not verified live; every other endpoint carries it at the top level. | The contract tests deserialise fixtures with `request_id` moved to the envelope (`fixture` entries in `known-unmodelled.json`); a nested copy would land in `Extra`. | Docs, 2026-09-11 |
| `single_sender_emails/add` and `remove` examples | `{"just_returns_this": "ok"}` / `"OK"` without an envelope; the `add` schema lists `request_id` only, the `remove` schema types `data` as a string. | Not verified live. | `AddAsync` returns `ApiResponse<JsonElement>`, `RemoveAsync` `ApiResponse<string>`; fixtures wrap the placeholders in the standard envelope. Record the live shape here after the first run. | Docs, 2026-09-11 |
| `subaccount/reopen` response | The schema describes an object (`id`, `email`, `name`); the example is the string `Successfully reopened subaccount test@example.com`, like `close`. | Not verified live. | `ReopenAsync` returns `ApiResponse<string>` following the example. If the live API returns an object, the call throws `Smtp2GoApiException` (body could not be parsed); use `Raw` meanwhile and report it. | Docs, 2026-09-11 |
| `subaccounts/search` `states` | Typed as a string with values `all`, `active`, `closed`, `suspended`. | As documented. | `SubaccountStateFilter`, one value per request (not a list). | Docs, 2026-09-11 |
| `sms/view-received` numbers | The example shows `source_address` and `destination_address` as JSON numbers while the schema says strings. | Not verified live. | `NumberOrStringConverter` reads either into `string`. | Docs, 2026-09-11 |
| `sms/view-sent` country field | The schema key is `destination_address_county` (sic); the example uses `destination_address_country`. | Not verified live. | Modelled as `destination_address_country`. | Docs, 2026-09-11 |
| `sms/send` `messages` | The schema documents a `messages` array (destination, message_id, status); the example omits it. | Not verified live. | `SmsSendResult.Messages` is optional. | Docs, 2026-09-11 |
| `domain/view` `from_master` | The response schema documents `from_master` ("delegated to the subaccount from the master account"); the example omits it. | Not verified live. | `SenderDomain.FromMaster` is optional. | Docs, 2026-09-11 |
| `ip_allow_list/*` | The 2026-07 changelog mentions an IP allow list with a `type` of SMTP or API; the reference index has no pages for it. | n/a | Not modelled; reachable through `Raw` once documented. | Docs, 2026-09-11 |
